## 2. 金融科技主要业务版图

| 业务                | 公开产品 / 能力                                 | PM 要理解的链条                                                      | 对商证的关系                               |
| ------------------- | ----------------------------------------------- | -------------------------------------------------------------------- | ------------------------------------------ |
| 商业支付与商户服务  | 微信支付，多类商户接入场景                      | 商户申请 / 权限 → 下单 / 支付 → 查询 / 通知 → 退款 → 账单 → 异常处理 | 本轮核心，公开规则与合成数据支撑           |
| 个人支付 / 金融应用 | 官方资料列零钱通、理财通、分付、腾讯微保等      | 用户需求 → 产品与合作机构 → 风险与适当性 → 服务 / 售后               | 认识业务边界；不做推荐或授信               |
| 跨境支付            | TenPay Global，收款、付款、汇兑、跨境与本地消费 | 商户 / 合作伙伴 → 市场与币种 → 支付方式 → 清算 / 结算 → 对账 / 合规  | 后续研究方向；本轮没有跨境数据或 API       |
| 支付生态连接        | 公众号、小程序、线上线下收款入口                | 消费场景与订单 → 支付确认 → 商户业务更新                             | 帮助理解支付状态为何不等于全部商户业务状态 |
| 模型与应用基础设施  | 腾讯混元 / TokenHub                             | 模型开通 → 后端鉴权 → 证据构建 → 生成 → 校验 / 回退                  | 提供接入代码，真实调用待密钥               |

金融应用通常包含合作金融机构和不同服务主体，不应把页面里的全部产品当作一个团队直接经营的同一牌照业务。此课程不讲未经核验的内部交易结算、授信模型或投资策略。

业务广度依据：[腾讯官方产品目录](https://www.tencent.com/zh-cn/what-we-create/everything-we-create/)、[腾讯 2025 年 ESG 报告：普惠金融产品与服务](https://static.www.tencent.com/uploads/2026/04/09/f6dbd30b3d8ca9c65f76f3d73b7da739.pdf)。前者为持续更新目录，后者报告年度为 2025；查阅日均为 2026-10-03。FiT 品牌官方入口为 [腾讯金融科技官网](https://www.fitgroup.com/home)，动态页面本轮未取得完整正文，具体业务事实优先采用上述可读取官方资料。

## 3. 公众号与小程序支付：支付是商户流程的一环

公开商户接入页区分公众号、线下场所、小程序、PC 网站与 APP。公众号与小程序是交易入口；商户系统仍需完成自己的订单状态、退款处理和对账。[微信支付：接入指引](https://pay.wechatpay.cn/static/applyment_guide/applyment_index.shtml)

小程序支付官方介绍描述了选购、确认付款、验密、支付结果展示、返回商户小程序和支付凭证等过程；结算还需核对场景规则，不能把前端显示支付成功直接当成银行到账。[微信支付：小程序支付产品介绍，更新 2025-07-15](https://pay.wechatpay.cn/doc/v3/merchant/4012791894)

训练采用的抽象链条如下。它是基于公开接口的产品概念图，不是腾讯后台架构：

```text
消费者：公众号 / 小程序 / 门店
        ↓ 发起订单与支付
商户：订单 / POS ← 查询与通知 → 支付状态
        ↓                         ↓
商户内部业务状态              退款状态与支付账单
        └──────── 核对范围与口径 ────────┘
                         ↓
                差异证据 → 人工核查
                         ↓
             处理结果确认 / 实际工单关闭
```

这解释了为什么“支付成功而 POS 未匹配”不直接证明平台漏结算，也解释了为什么商证只协助核查而不替业务认定损失。

## 4. TenPay Global：扩展视野，但不越过 MVP 边界

腾讯官方 2025-11-11 公告介绍 TenPay Global Checkout：面向微信小程序境外商户整合多种本地支付方式，首批市场为新加坡和中国澳门。该公告的后续市场计划不是“当前已经覆盖”的同义词。[腾讯官方：TenPay Global Checkout 公告](https://www.tencent.com/en-us/articles/2202220.html)

[TenPay Global 官方全球收单页面](https://www.tenpayglobal.com/checkout/)展示了小程序境外本地化场景与统一支付管理方向；[官方企业服务页](https://www.tenpayglobal.com/en/corporate/)介绍跨境业务解决方案。

对 PM 的启示是：未来异常核查可能加入币种、汇率、市场、支付方式和跨境结算口径。但这些都没有进入当前合成数据。**人民币账单规则不能直接迁移为 PayNow、海外银行卡或其他市场的退款承诺。**课程可以要求写一份“扩展调研清单”，不能称已经实现全球统一对账。

## 5. 为什么训练选择商户异常处理

| 方向                    | 可以证明的产品能力                             | 首轮困难与风险                                               | 首版决策                             |
| ----------------------- | ---------------------------------------------- | ------------------------------------------------------------ | ------------------------------------ |
| 商户对账 / 异常处理     | 金额口径、结构化证据、规则解释、人工责任与评测 | 尚需用户验证；不能推断到账或自动退款                         | 选择：边界明确，能做离线复验         |
| 智能营销                | 内容与分群、商户运营、实验归因                 | 缺真实流量 / 客群数据，无法证明转化与增量收益                | 延后：先明确权限、归因与试验条件     |
| 自动贷款审批 / 资金执行 | 授信流程、金融决策与合作机构服务               | 当前没有征信、授信数据或资金权限，缺少机构授权与风险验证条件 | 不纳入首版；另做权限、数据与风险调研 |

这是训练设计取舍，不是腾讯已公布的产品优先级。评审者应看到候选人如何缩小问题、验证价值和管理风险，而非堆砌全部业务名词。

## 6. 四类状态逐项标注

| 事项       | 公开业务规则                    | 假设训练情境                     | 当前代码 / 资料可复验项         | 后续接入 / 验证                    |
| ---------- | ------------------------------- | -------------------------------- | ------------------------------- | ---------------------------------- |
| 账单下载   | 官方次日生成与下载条件          | 9:30 商户投诉昨日账单不存在      | 规则解释与支持日期约束          | 真账单申请、签名、哈希和导入       |
| 退款异常   | 官方查询 / 通知与最终状态规则   | 客服没有收到回调，想直接重复退款 | 合成退款状态、解释和草稿        | 真回调、验签、幂等与状态回写       |
| 对账差异   | 官方账单结构 + 项目自定分析口径 | 财务把 POS 差额认定为平台损失    | 整数分金额与异常证据            | 脱敏历史数据和真实流程验证         |
| 混元解释   | 官方 TokenHub 接口协议          | 模型引用正确却改错金额           | 服务端接入与结构 / 引用检查代码 | 真实调用与语义 / 数字一致性评测    |
| 跨部门协作 | 无腾讯内部 SOP 来源             | 需求变更 / 技术资源延迟          | 训练文档与交付模板              | 实际课程操作验收，不是实际部门协作 |
| 灰度       | 无腾讯内部灰度标准来源          | 一例跨商户泄漏导致停止扩容       | 硬门和回滚训练设计              | 身份、数据层隔离、生产监控与试点   |

“已实现”只描述源码和可运行演示；评测成绩以实际执行报告为准。“训练完成”表示提交了练习并通过规则覆盖检查，不是获得腾讯实习认证。

## 7. 本课程的角色协作模型

PM 明确问题与范围；技术评估实现与依赖；数据 / 财务复核口径；安全 / 风险检查隔离和动作权限；客服 / 运营检查材料能否接续。以上是常见产品协作职责的模拟，不使用腾讯真实员工身份、具体部门名称或内部审批层级。

QQ 音乐、京东业务、游戏与其他内容业务不进入此课程的支付异常主线；除非真实用户需求和合作边界明确，否则无需为了展示“全腾讯”而硬性关联。
