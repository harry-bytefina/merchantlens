# 评测协议与真实结果

本作品有三层评测。默认可运行的是第一、二层；尚无模型密钥，第三层未执行。

## 1. 业务不变量与工程检查

通过 `npm test` 运行。独立测试包括固定样例金额复算、退款状态区分、修改源数据后重新发现差异、插入同订单号的跨商户数据不影响当前账单、无效作用域拒绝，以及模型适配器的异常响应、引用失效、超时与秘密信息边界。不能把工程测试数量当作真实用户样本量。

## 2. 固定场景回放

打开“评测实验室”，点击重新评测。用例保存在 `artifacts/evaluation-cases.json`，生成报告保存在 `artifacts/evaluation-report.json` 和 `.md`。每条检查意图、响应状态、预期来源是否命中、输出引用是否存在，以及被阻止的请求是否泄露账单证据。

金额数据指纹、构建时间和逐例结果全部可下载。固定用例是开发回归集，不是盲测集；通过率只能用于说明当前版本是否符合这些已定义的验收条件。

## 3. 真实模型评测（接入后执行）

配置腾讯云 TokenHub 后，冻结数据、规则、prompt 和模型版本，另外采样至少三类问题：日常解释、对抗/越权、证据不足。保存原始响应、引用集合、延迟、token 和人工标注；分开计算引用覆盖率、来源真正支撑结论的比例、金额一致性、拒答精确率/召回率、人工修订率、P95 延迟与每个有效闭环的成本。

接口校验引用 ID 不能判断句子是否真的由引用支持。例如引用 `K-REFUND` 却写“PROCESSING 必然已到账”仍可能通过格式校验，需要事实一致性标注。未来接入验收必须加入这种失败样本。

## 建议上线硬门（产品假设）

金额算错、越商户数据泄露、未经授权资金动作：发现任一实例，停止上线并回归复验。其他质量阈值、成本预算和放量条件应在真实场景标注后定标，具体计划见 PRD。

## 实习任务评分

实习任务台采用透明的规则 rubric：单选取舍、最低交付字数、必要业务概念是否覆盖。它是结构化学习反馈，不能理解复杂文章的全部含义，也不代表腾讯导师、招聘或实习绩效评价。修改答案并复验会保存学习记录。

## 当前不支持的结论

- 规则回归通过，不代表混元已验证。
- 合成差额可复核，不代表真实账单完整或财务结算已核平。
- 本地审核标记，不代表工单已送达外部部门。
- 课程交付完成，不代表腾讯实习经历。
