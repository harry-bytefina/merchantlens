# 腾讯模型接入与运行说明

这是围绕腾讯支付生态设计的个人 AI 产品研究作品，使用合成商户和账单数据，不是腾讯官方系统。默认模式完全在本地进行意图识别、证据检索、金额计算与异常核对。真实模型接入代码已实现；本轮未配置密钥、未开通模型、未验证真实线上模型调用，也未产生模型调用费用。

## 1. 两层答案及事实归属

浏览器和服务端使用同一份分析引擎。所有金额以整数“分”计算，规则确定订单差异、退款状态与手续费异常。模型只能对服务端重新计算的 `Answer` 及其引用证据生成解释摘要，不能写回金额、触发退款、改变账单或读取其他真实商户。

`POST /api/assist` 只接受用户问题和预定义的合成样本范围，拒绝客户端提交的 `answer`、密钥或额外动作字段。服务端先重新运行 `analyze(query, scope)`；越权、写操作、范围外和待澄清问题直接返回证据引擎的结果，不向模型转发。

模型返回必须为 `{ "text": "…", "citations": ["…"] }`，且引用数组非空、所有 ID 均位于本次服务端证据白名单。格式错误、未授权引用和缺少引用均返回错误，界面保留规则答案。**引用 ID 校验只能验证来源范围，无法单独证明每句话忠于证据。** 真实接入后仍需进行金额一致性、政策适用性、引用语义正确性、拒答稳定性的人工与模型评估；不得宣称已经消除所有幻觉。

## 2. 配置方式

要求 Node.js 24。先安装依赖并构建，再启动只监听本机的服务：

```sh
npm install
npm run build
node server/server.mjs
```

服务默认在 `http://127.0.0.1:5180`。开发前端另行使用 Vite 的 `/api` 代理；密钥永远不要添加到 `VITE_*` 变量或浏览器代码。

后续开通腾讯云服务后，复制 `.env.example` 为 `.env.local`，**仅在本机文件中填写密钥**。此文件应被 Git 忽略。启动方式：

```sh
node --env-file=.env.local server/server.mjs
```

| 变量               | 说明                                                                      |
| ------------------ | ------------------------------------------------------------------------- |
| `TOKENHUB_API_KEY` | 首选的 TokenHub 密钥；当前示例为空，不含真实凭据                          |
| `HUNYUAN_API_KEY`  | 可选的原混元平台密钥别名；两者同时存在时优先 TokenHub                     |
| `MODEL_BASE_URL`   | 必须是允许的官方 endpoint；默认广州 `https://tokenhub.tencentmaas.com/v1` |
| `MODEL_NAME`       | 必填；官方文档列出的 `hy3` 仅作为配置示例，须在对应站点开通后使用         |
| `PORT`             | 本机服务端口，默认 `5180`                                                 |

根据 [腾讯 TokenHub 官方语言模型调用指南](https://cloud.tencent.com/document/product/1823/130079)（核对日期：2026-10-03），广州 Base URL 为 `https://tokenhub.tencentmaas.com/v1`，新加坡为 `https://tokenhub-intl.tencentmaas.com/v1`；Chat Completions 使用 `/chat/completions` 和 Bearer 鉴权。广州与新加坡站点密钥不互通。适配器另允许 [原混元官方兼容接口](https://cloud.tencent.com/document/product/1729/111007) `https://api.hunyuan.cloud.tencent.com/v1`，但模型名与服务权限须以该平台配置为准；切换地址不代表密钥可跨平台使用。原平台已提示逐步迁移到 TokenHub，新开通服务优先使用新平台。

无需 SDK，使用 Node 内置 `fetch`。密钥不出现在状态接口、API 错误、打印输出或静态文件中。未开通模型、额度不足、无效密钥均以失败状态呈现，不能伪装成真实模型成功调用。

## 3. API 契约

### `GET /api/model-status`

```json
{
  "configured": false,
  "available": false,
  "provider": "Tencent TokenHub",
  "model": "",
  "mode": "evidence"
}
```

`configured` 仅表示本机密钥、模型名与地址通过配置校验；不证明鉴权有效、额度充足或模型已开通。`available` 仅在**本进程中最近一次真实摘要调用通过响应与引用校验后**为真，后续失败会置为假。查询状态不会触发模型调用或收费。mode 为 `evidence` 或 `hunyuan`，后者表示已配置接入路径，并非每条回答均来自模型。

### `POST /api/assist`

```json
{
  "query": "核对账单差异，列出需要人工处理的异常",
  "scope": {
    "merchantId": "demo-qinghe",
    "billDate": "2026-09-29"
  }
}
```

商户只允许 `demo-qinghe`、`demo-yunji`、`demo-xinghu`；账单日期只允许 `2026-09-28`、`2026-09-29`。问题非空且不超过 2000 字符，JSON 请求体不超过 16 KB。

成功模型响应为 `{ "text": "模型解释摘要", "model": "配置的模型名", "citations": ["允许的证据 ID"] }`。拒答和范围外问题返回 `model: "evidence-engine"`，不得显示为真实模型结果。错误响应为 `{ "error": "稳定错误码", "message": "可显示的中文提示" }`。

| HTTP 状态       | 含义与产品处理                                              |
| --------------- | ----------------------------------------------------------- |
| 400 / 413 / 415 | 请求或范围不合法、体积超限、内容类型不正确；请先修正输入    |
| 403             | 非本机来源、非法静态路径或模型范围被阻止                    |
| 502             | 模型连接失败、无效响应、JSON 错误或未授权引用；保留证据答案 |
| 503             | 未配置模型、权限/额度失败或模型繁忙；可继续演示本地证据能力 |
| 504             | 总调用预算超时；已停止请求，保留本地分析                    |

默认调用预算为 25 秒，包括重试等待；仅对 HTTP 429 / 503 重试一次，无无限重试。不跟随模型服务重定向，响应体最大 128 KB。不回显模型提供商的原始错误体。

## 4. 本机与发布边界

当前服务器只绑定 `127.0.0.1`，只允许本机 Host / Origin，不使用 `Access-Control-Allow-Origin: *`。静态内容只能来自 `dist`；目录穿越、点文件和越界符号链接受阻。

对外投递可优先部署不含密钥的静态演示版，评审仍可完整体验证据分析、账单核对和产品说明。若发布带真实 API 的版本，需要重新设计鉴权、同源入口、账户配额、限流和密钥管理；当前本机来源限制不能替代互联网场景的身份认证。应在获得托管账户和明确费用范围后再发布真实调用入口。

## 5. 已验证与尚未验证

`tests/server.test.mjs` 使用假密钥和模拟上游，验证了：输入范围、禁止客户端伪造事实、未知问题与写操作不调用模型、无密钥失败、来源保护、静态文件安全、响应大小、有效引用、错误 JSON、越界引用、失败信息脱敏、超时与有限重试。

这些属于工程行为测试。尚未验证真实腾讯模型的质量、端到端线上延迟、实际 token 成本、真实退款工单的业务适用性和大规模商户使用效果；作品演示指标不应被写成线上业绩。
